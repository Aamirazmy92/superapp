# Veyo plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins and marketplaces for Veyo with consented install, enable/disable, update and uninstall, contributing commands, agent presets, prompts/skills, MCP definitions and themes.

**Architecture:** Main-process service under `electron/plugins/` (manifest, files, registry, marketplace, git, service) exposed through narrow IPC in `main.cjs`/`preload.cjs`. The renderer has pure helpers in `src/pluginModel.ts`, the `Plugins` modal, and wiring in `App.tsx`, `CommandPalette`, `RunCommands`, agent pickers and `Settings`.

**Tech Stack:** Electron 44 (CommonJS main), React 19 + TypeScript, node:test, Playwright Electron.

**Spec:** `docs/superpowers/specs/2026-10-08-plugins-design.md`

**Execution note:** the user delegated choices ("do what you think is best"). Tasks list files, interfaces and required test cases. Code is written during execution, not duplicated here.

## Global Constraints

- Plugin/marketplace names: `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 64 chars; `local` and `git` are reserved marketplace names.
- Limits: manifest ≤ 256 KB, file ≤ 1 MB, ≤ 2,000 files, ≤ 50 MB, depth ≤ 16, ≤ 50 contributions per kind, marketplace ≤ 4 MB / 1,000 entries.
- No symlinks; all manifest paths relative, no `..`, realpath inside the plugin root.
- Nothing from a plugin executes during preview/install. Commands run only in a visible terminal via the argv array.
- Git: `execFile` array, 60 s timeout, no prompts, shallow clone, no submodules, fsmonitor/hooks disabled.
- All IPC goes through `handle()` (sender check) and validates every argument.
- Unset `VEYO_DEV_URL` for Electron tests; `terminal-cursor.electron.cjs` is a known, unrelated failure.

## Review Focus

1. A Windows path with spaces or `'` in `${projectRoot}`/`${pluginRoot}`: the command still runs with correct quoting (PowerShell path quotes the program too). Test: run-spec builder unit test with `C:\a b\it's`.
2. A plugin directory deleted or edited on disk after install: the plugin shows an error state and contributes nothing, without crashing the list. Test: corrupt the manifest after install, then `state()` reports `error` and `contributions()` excludes it.
3. A marketplace with one bad entry among good ones: the good entries still show; the bad one is listed with its error. Test in marketplace parsing.
4. Two installs of the same plugin (user + project): project wins for that project; disabling the project install falls back to the user one. Test in scope resolution.
5. App restart mid-install (staging leftovers): staging is cleared at start-up and the registry is unchanged. Test: service init removes `staging/*`.

### Task 1: Manifest validation and plugin loading (stage 1)

**Files:** Create `electron/plugins/manifest.cjs`, `electron/plugins/files.cjs`; Test `tests/plugins.test.cjs`

**Produces:**
- `files.scanTree(root) -> Promise<{files: string[] (posix rel), bytes}>`: throws on symlink, limits, depth.
- `files.copyTree(src, dest, {exclude?: string[]})`: scan first, then copy regular files.
- `manifest.validateManifest(raw, {format:'veyo'|'claude'}) -> normalized manifest` (throws `PluginError` with a readable `message`).
- `manifest.loadPlugin(root, {appVersion, fallbackVersion?}) -> Promise<Plugin>` where `Plugin = {name, version, description, author, license, homepage, minAppVersion, format, compatible, contributes: {commands, agents, prompts, skills, mcpServers, themes}, unsupported: string[], readme?: string}`; prompts/skills include `{id, title, description, body}`.
- `manifest.checkArgs(args, {batch})`, `manifest.BYPASS_FLAGS`, `semver.compare(a,b)`.

- [ ] Tests: valid veyo manifest; bad name; bad semver; absolute path; `../` path; path escaping through realpath; symlink in tree rejected; oversized manifest; too many files; >50 commands; arg with `"`; agent with `--dangerously-skip-permissions`; `program` with a slash that isn't `${pluginRoot}/`; Claude import infers prompts/skills/mcp and lists hooks/agents as unsupported; minAppVersion newer → `compatible:false`; theme with a non-hex colour rejected.
- [ ] Implement; `npm test` passes.

### Task 2: Registry and scope resolution (stage 1)

**Files:** Create `electron/plugins/registry.cjs`; Test `tests/plugins.test.cjs`

**Produces:**
- `createRegistry(file, writeAtomic) -> {load(), get(), save(mutator)}`: `save` serializes writes on a queue; the file shape is in the spec.
- `normalizeRegistry(raw)` drops malformed entries.
- `entryKey(entry) = id + '|' + scope + '|' + (projectId||'')`.
- `activeEntries(entries, projectId) -> entries` (enabled, scope match, project overrides user per id).

- [ ] Tests: normalize drops junk; atomic write leaves the previous file intact if the write throws; concurrent `save` calls both apply; scope resolution (Review Focus 4); name collision helper `conflictingInstall(entries, name, marketplace)`.
